# 毒 / 灼烧专项数值评审（2026-10-14）

本轮只做评审与隔离实验，没有修改产品数值、玩法、源码、存档或运行服务。结论来自当前工作区的真实 `battleStart` / `battlePreview` / `battleEnemyPreview` / `battleTurn`，不是另写伤害公式的模拟器。

## 优先结论

1. **先修清毒计量一致性，再决定毒伤是否需要加强。** 普通 PvE 中玩家给 NPC 的毒仍使用 `poisonDamage=-1` 层数模式，NPC 治疗清除 2 点后回写时向下取整成整层。化神样本从 3 层 / 59 每跳变为 2 层 / 39 每跳，实际清除约 20 点；玩家被同量毒伤命中，治疗后仅从 59 降为 57。精确模式夹具同样保留 3 层，降为 57。这是明确的双方数值不一致。
2. **毒和灼烧的每跳伤害均绕过护盾及减伤；引爆则受两者影响。** 金丹靶有 267 护盾与 35% 减伤时，完整火构筑吐焰直伤为 0，仍施加每跳 40 灼烧；完整毒构筑腐毒直伤为 0，仍施加 5 层、首跳 14。接着在补齐护盾的靶上引爆，两者都造成 0 气血伤害并清空状态。不能把“引爆面板伤害高”直接当作稳定兑现伤害。
3. **完整火构筑的持续伤害成长远高于裸身，完整毒构筑还要计入回血与终结。** 化神单次裸焰火三跳累计 570、裸腐毒 400；现有完整火构筑吐焰 1514、完整毒构筑腐毒 634。完整毒构筑在半血时施毒实际回复 260，约最大气血 5.9%，并在该回合末因木道节点再回复 44。因此只比较 DOT 损血会低估毒构筑的整体收益。
4. **没有发现同一已消耗状态被引爆后再次跳伤。** 玩家火爆 / 毒爆立即清空状态，紧接的 `end` 对应 DOT 为 0。NPC 行动前先结算一次 DOT，再用扣除持续回合后的状态引爆，下一回合没有残余跳伤。毒爆不按剩余回合缩减，因此“先跳一轮再爆”可以获得一轮 DOT 加完整层数爆发；这是现有机制的收益，不是重复调用结算。
5. **结算次序给予玩家机会优势，需要明确写进规则。** 玩家新施加状态当次 `end` 就跳，后手 NPC 的新施加状态要下一次 `end` 才跳。普通 PvE 双方各 1 气血、各带 2 点活跃灼烧时，敌人先死，玩家自己的当轮 DOT 被跳过，真实结果为玩家获胜、场外健康度 1。影身代码有不同的同时致死处理；本轮未把影身结果混作普通 PvE。

## 状态与结算核查

权威位置：`combat/battle_scaling.h:5` 与 `battle_scaling.cpp` 提供 `战力×0.3+18`；`combat/battle.cpp:1111`（毒爆）、`:1121`（火爆）、`:1168`（施毒）、`:1184`（施火）、`:1269`（持续伤害）、`:1335`（NPC视角回写）、`:1969`（回合顺序）。

- 腐毒 / 碧落毒雨基准新增 3 层，其余毒类新增 2 层，再加向下取整后的功法层数收益与状态倍率。毒上限 99，所有再次施毒刷新为 3 回合。每跳 `round(基底×0.035×层数)`，先损血与扣持续回合，再为仍活跃的毒加 `floor(poisonGrowth)`；到期先清零，不再增长。没有逐层衰减。
- 灼烧是每跳伤害量叠加，上限 1,000,000 是安全限制，通常不构成平衡上限。新增量来自同一伤害基底、`burnBonus`、木生火 1.5 倍、火道 2 节点 2 倍、`burnStack` 与状态倍率。所有再施火刷新为 3 回合；没有每轮伤害衰减或自动增长。完整火的相生连招尚能增加新的灼烧量，本表使用非相生单牌。
- 毒伤 / 灼烧跳伤均直接扣气血，绕过护盾、守势与被动减伤。施加牌即便直伤被全挡，仍施加状态。毒爆 / 火爆先把额外伤害加到直接攻击，再统一减伤、吸盾。
- 治疗只按 `floor(poisonCleanse)` 减少自身每跳毒伤，降至 0 才解除中毒。没有在此路径净化灼烧，也没有把“忘机咒”误当成状态净化。

## 双向参数、出手顺序与净化差异

五境均设置同样的裸身 / 现有完整构筑被动，使用普通 NPC 完整卡牌入口镜像施火 / 施毒。双方实际直伤、施加量、连续三跳与毒增长相等。化神镜像示例：裸焰火 `402→56/56/56`，裸腐毒 `223→59/59/59`，完整吐焰 `686→276/276/276`，完整腐毒 `223→98/137/176`。玩家与 NPC 同样都能在对方 30% 最大气血护盾、35% 减伤下施加状态，并由 DOT 穿过防护。

**相等的是系数，结算时点并不相等。** 玩家出牌→双方DOT→NPC出牌。NPC 首个 `end` 只有直接攻击，新施加状态保留完整3回合；下一 `end` 开始跳。快速 NPC 在开战入口已先施法，则玩家首个 `end` 就会吃其 DOT。

| 先后手 | 开战结束 | 玩家首次end |
|---|---|---|
| 玩家先手 | 玩家614，无毒 | NPC腐毒32；玩家582，毒伤9 / 剩余3回合，当轮未跳 |

NPC 引爆探针也确认先扣持续期：灼烧8 / 剩3回合，完整 `end` 为跳8+火爆69=77；剩1回合为跳8+基础火爆53=61。毒3层 / 剩3回合为跳9+毒爆80=89；剩1回合已在动作前到期，为跳9+基础毒爆36=45。预览逐例等于实伤，之后残余伤害0。玩家可以在到期前主动毒爆，NPC 的计划在同一完整回合先经过到期处理，最后一轮毒爆时机存在差别。

旧兼容 / 简化 `poison` 意图在 `battle.cpp:2021` 使用基底 `×0.05`，取当前毒伤与新增毒伤的最大值并刷新3回合。它不进行上述3层叠加，与新的 NPC 卡牌路径不同。本轮仅源码核对这条兼容分支，没有把它当新 NPC 数值统计，也未声称所有敌方毒均同一施加模型。

## 候选调整与评审顺序

本轮没有应用以下候选，也没有假装已测出候选胜率。

1. **优先修正清毒的双方计量。** 在普通新战斗采用现有精确每跳字段或让层数模式保留精确清毒余量，避免平减2点被放大成清整层。修正位置 `battleSaveEnemyView` 与普通战斗初始化；已有在途 `-1` 语义和旧档必须有明确迁移边界，不应直接把旧毒伤归零。保留毒层供毒爆的语义也需一起评审。
2. **明确 DOT 与引爆的防护契约和时间契约。** 如果持续伤害穿盾 / 穿减伤、引爆可被挡是有意设定，就应在预览中说明，并提示引爆会放弃的剩余跳伤；不建议为追求面板一致而直接把所有 DOT 拉进护盾通道。快速NPC / 后手NPC的首跳，以及普通PvE同时致死玩家优先，属于规则选择，先明确再谈改动。
