# 2026-10-12 桌面页面修复与新版布局

本文件记录桌面生产 JS、导航和必要 CSS 的最终改动；移动版、v2、登录、天机、排行榜和反馈模块未修改。保留工作区已有后端重构与用户自行修改的文字；本子任务没有提交或推送。

## 已落地

- 新顶级入口：任务、工坊、坊市、行囊与面板。任务集中城中、宗门、悬赏、支线；工坊单列炼丹、炼器、丹炉；坊市保留交易与书坊交易。
- 行囊列出真实拥有的法宝、丹药、材料、草药和其他物品，不包含功法、神通。可按类型和品阶筛选；丹药按 `pillCatalog` 显示中文名、当前真实服用效果与丹毒，服用按钮调用原 `use-pill`。当前装备与丹毒在侧面板可见。
- 人物详细属性与中文天赋移到行囊“人物面板”；声望用途与获取说明也保留在此。成就页去掉重复人物档案，达成条目显示“已达成”，进度条限于 0–100%。
- 侧栏立绘下显示资质、悟性、福缘。颜色已在实际截图中检查并改为适合深色背景的高对比颜色。
- 岁月行卷默认 360px，可通过右下角原生手柄上下拖动，限制 180–900px，使用本机 `localStorage` 保存高度。
- 日常五项计划改为紧凑 `select`，始终只有一个当前计划；保留选中计划描述和服务端收益摘要。
- 纪事分类按钮缺少 `data-logfilter` 接收处理是无响应的根因。补委托 handler 后，全部、大事、自身、同道、宗门、天下能更新本地时间线。支线阅读与分支 handler 原本存在，真实 DOM 点击验证其可打开并选择两项分支。
- 炼丹按权威 `ingredients.required/owned`、`stoneCost`、`durabilityCost` 和所选 `batch` 显示整批缺口、成本和耗时，切换炉数立即重绘。不改变配方、成功率、每炉产出、耗时或材料消耗。炼丹前与进行中的安排都消费真实 `pillCatalog` 效果。
- 炼器消费原 `/api/forge-preview`：被动属性、神通数值、状态、条件及铭刻后预览。进行中的炼器锁定已开炉的配料，并显示本炉剩余时间与效果查看入口。
- 一键补料：只读 `/api/craft/materials/quote` 后显示 `materials`、`totalCost` 与禁用原因；确认 `/api/craft/materials/buy` 同配方请求并附 `expectedCost`，只买缺口。炼丹使用当前炉数；炼器界面每次准备一件，不改变原每次开炉一件的规则。
- 法宝回收直接读取 `state.gears[].salvage`，确认前显示返还材料、`costStones`、`estimated` 和 `sourceNote`；确认后调用原 `/api/gear/salvage`。不沿用旧“分解返灵石”说明。
- NPC 丹药赠礼查 `pillCatalog`，不展示药品内部编号。战斗冷却优先查 `battle.artifacts` 中文名称，避免 `artifact:*` 内部编号。
- `nextMana` 是下一轮总灵力设置值，文案改为“下回合灵力恢复到 N 点”；神通的增量回复继续按权威 `preview.text` 展示。
- 秘境战斗标题为“秘境斗法”。按核心实现说明：本场不致死；战败或斗法撤离结束探索，只带回一半已得物资，未通关入口消失，临时神通和遗物离境消散。
- 兼容旧 `#equipment`、`#poison`、`#forge`、`#brew`、`#kit`、`#market/brew`、`#market/kit`、`#economy/forge` 链接；法宝侧栏“查看行囊装备”指向新行囊。
- 建号界面消费 `build-options.pendingLegacyPoints`，说明新增传承已计入当前预算、成功开新人生才结算。前端预算始终来自服务端；自动结算与失败原子性由根任务后端处理。

## 截图服药入口复核

用户指出人物面板截图出现绿色“服用化淤丹”。DOM 核实该元素是上一服药动作留下的 `#toast` 状态提示（div、role=status、pointer-events:none），并非人物面板按钮；截图在其 2.6 秒自动隐藏前取得。页面与子页切换现在立即清理该提示，人物面板截图不再残留类似固定入口的文字。

服药流程进一步明确：只在行囊具体丹药卡中点击“查看效果与服用”，展开持有量、服务端效果和丹毒，再点击该丹药详情内的服用按钮。人物面板没有 `data-action="use-pill"` 按钮。真实 DOM 回归新增这两项断言并通过，已更新人物面板截图。
