## 定位结果

测试使用独立合成角色：seed 4271、720 名 NPC、化神阶段，洞府在武陵城。密集灵田夹具为八格六阶草药，每格 99 份错开进度的种苗。没有读取或操作玩家存档，也没有连接现有 8107/8108 服务。

GCC Debug/O0 核心的分离测量表明，空灵田过月的真实日历成本只有约 3.6 ms；完整 state 构造约 116–118 ms，编码约 34–35 ms，完整存档构造/编码约 93–95 ms。MSVC Debug 的同类视图、编码和存档明显更慢。因此不能把整次点击的等待全部归因于“推进30天”，也不能只测试过月或只有种满灵田的角色。

确定的热点：

1. 灵田每个真实日调用完整地块视图，而视图又从当前储备预演一直到所有批次成熟。这使每天结算重复计算不需要的跨日预报。
2. 每个整数编码都构造 `ostringstream` 和 locale；世界、NPC、背包和目录响应包含大量整数。
3. NPC 授业列表反复读取固定功法说明，每次重新拼接完全相同的触发长文本。

## 实际改动

- 灵田拆为“下一日权威报价值”和“给该报价值补充成熟预报”；真实日 tick 仅使用单日报价值，纯视图保留原逐日隔离预演。自然成熟最后一天不收费、成熟封顶、储备不足不部分扣费、离家成长及同日幂等均不变。
- JSON 仅对有符号 32 位范围内的精确整数使用 `to_chars`。负零、范围外数值、非整数及非有限值保持原分支；小数仍使用17位精度。逐字节旧格式检查覆盖边界、负零、余数、极值、非有限值及分布整数样本。
- `findManualInfo` 委托一次构造的不可变内容目录，仅缓存功法固有定义/触发说明。玩家学习资格、已学状态、境界、背包、好感及交易报价仍实时计算。

## 实测数字及局限

以下是同机诊断样本，单位 ms；不是性能门禁或所有玩家的延迟承诺。计时探针与原/新独立二进制及日志保存在本工作区忽略的 `build-backend-desktop` 目录。

| 测量 | 修改前 | 修改后 |
| --- | ---: | ---: |
| GCC Debug，密集灵田推进30个真实日 | 46.25 | 7.70 |
| GCC Debug，密集灵田推进360个真实日 | 330.38 | 115.83 |
| GCC Debug，密集灵田推进3600个真实日 | 1997.31 | 1158.74 |
| GCC Debug，空灵田 state 编码 | 34.58 | 24.71 |
| MSVC Debug，功法定义查询8000次 | 207.20 | 8.56 |
| MSVC Debug，完整社交视图 | 217–232 | 144–146 |

自然日历探针通过 `calendarBattleDay` 执行共有的真实世界日，包含月/年边界、NPC、兽潮、灵田和排毒；它不模拟日常计划奖励或工作完成。另通过真实核心 `/api/advance` 入口测了 1/30/360/3600 天：均成功，十年请求在第1080天因真实事件暂停，符合遇事停止规则；不能把它当成已无中断地推进整整十年。

API 端到端数字受到同时编译和系统负荷影响明显，本记录不据单次结果宣称整体点击延迟提升。最终 Release 服务的真实 HTTP、前端绘制及交互测量由主任务另行执行并记录；这里不将未执行项或历史全库测试当作本轮结论。

另外以真实 `travelBegin`、`ecoBegin` 建立合法工作，再通过核心 `/api/advance` 推进：武陵城至永安镇步行实际7天完成；一阶首丹方实际4天完成。两者响应200、剩余工作归零、报告done，日志 `time-action-work-after.log`。该测试使用独立内存会话与独立存档目录，包含真实工作/行程完成分发，但不包含网络和浏览器绘制耗时。

定向验证命令为 GCC 链接 `test_time_performance.cpp` 与 `test_cave_garden.cpp` 到当前 `nzcore`，共915项通过、0失败；日志 `time-performance-tests-final.log`。完整存档摘要对照为 `advance-performance-before.log` / `advance-performance-after.log`：空田/密集田 × 1/30/360/3600天八组均一致，包含日历、RNG、NPC、费用、成长及纪事。
