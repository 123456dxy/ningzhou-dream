## 范围与结果

原实现对每个有效格式的 POST 都复制全服 `entries_`、`encounters_`，包括最终只返回 409 的旧版本行动。非法战斗行动还会复制赋值两个完整容器来回滚。

本次只改内存事务边界，不修改存档格式、版本、原子写入流程、HTTP 合约或战斗规则：

- 验证、幂等和版本检查先执行，拒绝的请求无需复制全服记录。
- 报名失败只删除本次新建留影并恢复 `nextId_`。若既有存储的 ID 计数器发生碰撞，在写入前明确拒绝，避免误删已有留影。
- 挑战暂存本账号原遭遇的 map 节点。写入失败时恢复该节点、删除本次尝试并恢复 ID；成功后才释放旧遭遇。
- 行动只复制当前遭遇，单独保留对应尝试的结算结果。非法行动或写入失败通过移动恢复战斗、RNG、回执、版本和积分状态。

## 可重现基准

`tools/tianji-rollback-benchmark.cpp` 通过公开 Store API 创建初始有效留影，使用固定战斗种子生成独立临时测试存储。每组为 10、100、512 个留影，分别保留相同数量的最近遭遇；每场包含 32 行战报、16 条合成历史回执。文件分别为 144,117、1,442,092、7,385,206 字节。该高占用代表性夹具不是玩家生产流量或真实并发测试。

Linux x86_64，GCC 14.2.0，C++20，`-O2`。比较同一工具链接的优化前/后核心库。每个旧版本拒绝测 101 次，非法行动测 31 次，其余操作各测 7 次，报告单次中位耗时。数据准备和加载不计时；写入操作包含完整序列化、磁盘写入、同步以及成功后的完整状态响应。

内存为自带等价分配计数器记录的 **C++ 堆有效载荷峰值增量**，不是 RSS；不包含分配器元数据或内联栈对象，不能当作进程总内存。总申请字节数单列在 [原始结果](tianji-rollback-results.csv)。表中 B 为字节；若使用 MB 则按 1,000,000 B，MiB 按 1,048,576 B。

| 留影/最近遭遇数 | 旧版本拒绝，优化前→后 | 拒绝额外堆峰值，前→后 | 正常回合提交额外堆峰值，前→后 |
| --- | --- | --- | --- |
| 10 / 10 | 67.46→2.73 µs | 263,583→2,703 B | 3,354,787→3,105,440 B |
| 100 / 100 | 679.21→3.38 µs | 2,613,103→2,703 B | 33,486,070→30,887,219 B |
| 512 / 512 | 9,461.21→6.99 µs | 13,368,351→2,703 B | 171,388,486→158,034,387 B |

512 份记录时，非法行动从 20,733.11 µs / 13,368,279 B 降至 12.23 µs / 12,828 B。正常提交的额外堆峰值减少约 7.8%。

**完整文件持久化仍是主要成本。** 512 份记录时正常回合提交为 500.10→496.33 ms，基本未变；终局提交为 521.96→555.40 ms，也没有稳定加速证据。单机负载和文件同步会影响耗时，不能把拒绝路径的改善宣传为所有行动的同等提速。扩大生产容量仍需单独设计分区/数据库及迁移，本补丁没有提前改写存储架构。

复现（两个版本各自构建并链接同一基准源文件）：

```sh
cmake -S . -B build
cmake --build build -j2
g++ -std=c++20 -O2 -I src -I . tools/tianji-rollback-benchmark.cpp \
  build/libnzcore.a -pthread -o build/tianji-rollback-benchmark
build/tianji-rollback-benchmark > benchmark.csv
```

工具不接收真实数据目录，每次自行创建临时目录并在成功结束后删除。

原始结果的 `baseline` / `optimized` 是上表的成对测量；`optimized_smoke` 是最终重编译后的复核。最终复核的堆计数相同，512 份记录正常回合提交为 521.84 ms，再次确认完整文件写入仍约半秒。基准工具以 `-Wall -Wextra` 编译无警告。

## 验证与接力

新增黑盒回归覆盖：首次报名和 ID 恢复、首次挑战及尝试清理、替换旧终局遭遇、非法行动、非终局行动、带积分终局行动、无关账号遭遇隔离、失败后的相同请求重试、成功和重启后的幂等、损坏 ID 计数器碰撞。

回滚校验通过另一次独立写入将恢复后的内存落盘，再逐项比较原始完整存储；因此包含未暴露给客户端的 RNG、敌方牌堆和请求回执，避免只检查可见版本号。

最终版本验证：核心 4,610 项通过（天机专项 205 项）；天机 HTTP 94/94；现有多人脚本 49/49；前端通用 235/235、天机 UI 67/67。独立审查发现的 ID 碰撞边界已修复并补回归。

本报告记录代码和隔离环境验证；发布状态以提交和审阅记录为准，生产部署不在本次范围。接力发布时只带本补丁，不覆盖玩家试玩目录。保持既有整目录一致备份和回滚要求；本补丁不需要数据迁移。
