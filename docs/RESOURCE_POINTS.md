# 资源点争夺模块：隔离骨架与实施方案

更新时间：2026-10-13。

本轮交付是**默认关闭、无法通过误开参数开放玩法的模块骨架**。已经定义配置、能力闸门、受控资源点 ID、内部开发目录和无副作用拒绝入口；没有实现抢占、守卫、产出、自动争夺或地图操作按钮。以下玩法、状态及接口分阶段方案是后续设计，不能当作本轮已经可游玩的功能。

## 参考与本地设计范围

《鬼谷八荒》的官方商店说明将宗门经营区分为弟子出征、长老调配和宗主制定攻防计划，包含灵矿等资源点的争夺。借鉴的是“占领资源—承担防守—获得宗门经营收益”的循环。[官方 Steam 商店介绍](https://store.steampowered.com/app/1468810/_/?l=schinese)

2021 年《宗门·天骄》更新存在官方公告；对应的 Steam 社区玩法介绍进一步描述了无主资源点、已有宗门所有者、增援与阵眼争夺。公告正文目前主要以图片展示，本文不据其推断精确公式。下文的经营权、时间、状态机、隔离方式及验收条件均为宁州一梦的本地方案，具体数值不宣称与参考游戏一致。[官方更新公告](https://steamcommunity.com/games/1468810/announcements/detail/3028100732074416496?l=schinese)、[Steam 社区玩法介绍](https://steamcommunity.com/app/1468810/discussions/0/3118172724621705341/?l=schinese)

目标是让地图地点有长期经营与宗门竞争价值，同时确保未完成模块关闭后，当前旅行、坊市、采药、后山、宗门、兽潮和秘境继续正常运行。

## 本轮实现边界

| 内容 | 当前实现 | 所有者与依赖 |
| --- | --- | --- |
| `Config.Enabled` | 默认 `false` 的部署配置值 | 应用入口组装，不属于角色存档，不允许玩家请求修改 |
| `GameplayReady` | 固定 `false` 的独立就绪闸门 | 模块实现；修改它会触发骨架静态断言，需要整体完成规则及验收 |
| `mfCapability` | 关闭返回 `Disabled`；请求开启返回 `Unavailable` | 纯查询，不接触 `Game` |
| `PointId` | 只能由不可变目录或严格解析建立的强类型 ID | 持有静态词表视图，可复制，无外部缓冲区借用 |
| `mfDevelopmentCatalog` | 18 项内部研发预案 | 不可变静态目录，不生成所有权或奖励，不对玩家开放 |
| `mfVisiblePoints` | 始终空集合 | 仅保留未来能力边界；不初始化游戏状态 |
| `mfTryAction` | 五类动作及非法请求全部明确拒绝 | 不读取或修改游戏，不扣钱、不建任务、不写纪事、不耗时或消耗 RNG |
| 运行状态／持久化 | 未加入 `Game`，未新增存档字段 | 不更改当前 codec、加载补全或状态校验 |
| 时间和收益 | 无日历钩子、无月产出、无 NPC 自动行为 | 不接入 `calendar` / `worldYear` / 既有地点服务 |
| HTTP 与 UI | 没有资源点动作 route 或地图入口 | 应用可在只读 `/api/mode` 中报告部署请求和不可用状态 |

源码为 `src/core/resource_points.h` 与 `src/core/exploration/resource_points.cpp`。模块仅依赖标准库；头文件前向声明既有 `nz::Game`，不引入战斗、地点服务、经济、存档或 HTTP 私有实现。测试单独使用既有公开创建／序列化入口。

应用组装约定：`--enable-resource-points` 只能将 `Config.Enabled` 设为真。当前 `/api/mode` 的能力快照仍应为 `available=false`、`mutationsAllowed=false`、`status="unavailable"`。没有参数时为 `requested=false`、`status="disabled"`。前端不能单凭 `requested=true` 显示功能；须同时满足真正的 `available` 与 `mutationsAllowed`，当前两者始终为假。

## 地点与资源点分开建模

地点是旅行、人物活动及城市服务的锚点；资源点是地点上的**经营权益**。取得经营权不会阻止其他修士进入城市、使用坊市、学习或完成原有任务。无经营权时也可以继续原有采药和后山探访。

| 类型 | 研发预案锚点 | 后续拟提供收益 | 权属设计 |
| --- | --- | --- | --- |
| 城池经营权 `CityFranchise` | 武陵、逸风、云汐、天星、广陵、东石谷、永安 | 有上限的月度灵石经营收益 | 初始城池议事势力；挑战争夺的是经营权，不摧毁城市 |
| 药田 `HerbField` | 风雷谷、连石山、方壶山、沃焦山、正阳山 | 配置中明确的药材品类、数量及品阶 | 初始对应五宗；小型无主药田在以后阶段加入 |
| 灵矿 `OreMine` | 同上五处后山 | 配置中明确的炼器材料 | 初始对应五宗；与旧低阶采矿服务独立 |
| 灵脉经营权 `SpiritVein` | 青石灵脉 | 灵石／灵核等已配置资源 | 存在旧所有权流程，需专门接入阶段，当前仅是预案 |

例：`wuling.trade_right` 与 `lianshi.herb_field` 是资源点稳定 ID；`wuling`、`lianshi` 继续是地点 ID。中文标题可修改，不能用于规则匹配。目录位置是现有地图锚点，并不表示该地已实装新药田或矿山。

城池、宗门、玩家和无主状态应使用具名权属分类。正式状态的所有者应使用强类型城池议事势力 ID、宗门 ID 或人物 ID，不把 NPC 名字、门派中文名和账号名称混为同一个字符串键。控制者记录只负责所有权，不负责修改既有 NPC 生死、宗门传承或市场行情。

## 后续玩法建议

### 占领与防守循环

建议先开放少量低阶野外点，再加入宗门后山，最后实现城池经营权竞争。

1. 地图查看所有者、资源品阶、每月净产出、库存上限、守卫境界、争夺预计耗时和费用；只读操作不能掷结果或补资源。
2. 玩家抵达地点后提交占领或挑战。无主点需要清除守点妖兽并支付经营准备成本，避免无限免费扩张；宗门点的争夺以宗门任务授权或相应职位资格参加。
3. 初版争夺采用固定的前哨、核心守卫两场战斗。全部获胜才转移权益；退却、败北、超时不转移，已提交的筹备费用按清晰规则结算。这样先复用现有卡牌战斗，避免第一版同时开发大型军团战。
4. 首个完整生产周期后产生收益，进入独立资源点仓库；领取前检查玩家行囊容量并整体提交。攻占当天不立刻发整月奖励。
5. 占领后建议 30 天保护期、同一进攻方失败后 7 天冷却。守卫配置、费用与难度随点位品阶变化，不能仅因玩家境界提高就自动把同一个小药田升级为高阶材料源。
6. NPC 势力每月有限次数争夺。结果进入资源点纪事并保留明确进攻方、守卫、归属变化和收益账本；高阶点与完整门派构筑形成自然门槛。

这里的两个战斗节点、30 天保护期和 7 天冷却是建议起始配置，尚未启用。争夺耗时应集中报价；若采用每轮一天，必须走统一世界日推进并处理跨月、跨年、寿尽、兽潮到期和回档，不能在资源点代码直接写 `clock.days`。

### 守卫与 NPC

守卫优先引用在世且归属正确的真实 NPC，并记录稳定人物 ID、派驻职责及配置修订号；必要的守点妖兽从点位规则表生成。沿用 `artNpcLoadout` 和现有门派构筑，不按对手姓名判断神通，不临时篡改世界 NPC 的境界、好感或永久装备来拼出守卫。

守卫陨落、转宗、换岗或境界变化后，在真实动作边界重新验证。玩家开始挑战时冻结该场敌方战斗快照，完成时校验所有权修订号，防止过期挑战覆盖已经被第三方占领的点。NPC 之间的抽象战果应采用模块自有随机状态，避免加入一个经济系统后改变原有奇遇和战斗随机序列；查询只能展示已确定事实。

### 收益、成本与容量

- 月产出、驻守维护费、保护期和品阶上限统一放资源点规则表。预览、开工、月结和领取使用同一来源，不由前端重算。
- 城池经营权从独立有上限的产出规则取得净收益；不扣当前坊市的玩家回收预算，也不通过玩家自买自卖反复制造税收。
- 药田与矿山产出必须使用受控材料 ID，并明确点位等级与所需守卫；低阶点以一、二阶材料为主，高阶资源需要独立资格、成本与竞争。
- 宗门所有点的收益进独立经营账簿，再通过已定义的贡献奖励入口分给参战弟子；个人点收益进入个人资源点仓库。不能每个月无条件给每位门人发一份完整产出。
- 建议最多储存三个完整生产周期；满仓后暂停新增，界面说明停产原因。余额和库存采用既有容量限制及溢出校验。
- `LastSettledMonth` 确保每周期仅结算一次；领取和占领完成均有动作标识与所有权修订校验，重复提交或回复丢失不能重复发奖。

## 后续状态与模块职责

以下是正式实现阶段的概念模型，当前没有这些 `Game` 字段：

| 模型 | 负责的信息 | 不负责的信息 |
| --- | --- | --- |
| `PointWorld` | 点位状态集合、规则版本、独立随机状态 | 玩家账号、HTTP 会话、原世界 RNG |
| `PointState` | 强 ID、所有者、等级、守卫 ID、库存、保护期、最后结算月、归属修订号 | NPC 完整人物副本、原坊市库存 |
| `CaptureRun` | 点位、预期归属修订、筹备报价、攻防快照、当前节点、截止日、结果领取标记 | 重新发明牌堆、伤害或悟道规则 |
| `OwnershipChange` | 原／新控制者、原因、动作标识、日期 | 根据文字猜测谁赢了 |
| `SettlementQuote` | 真实产出、维护成本、容量和可领取项 | 自动保存或界面字符串拼装 |

领域查询和命令留在 `ResourcePoints`；战斗仍由 combat 负责，日历由 simulation 推进。应用编排向资源点模块传已验证的战斗完成事实；模块只提交本模块权属与账本。HTTP 层只做协议转换、访问策略和动作后保存。不得继续往 `api.cpp` 或 `app.mjs` 堆公式。

后续新持久状态宜集中为可选的资源点运行态，关闭时不创建、不补全、不结算。用户本轮不要求历史兼容，但正式状态仍必须有完整编解码和领域校验，拒绝未知点、重复所有者、负库存、未来结算月和非法守卫引用。关闭期间的时间不得在重新开启时一次补发收益。部署开关不是热切换按钮；在途资源点工作的关闭和恢复契约须在阶段三完成并验收后再允许正式开放。

## 现有耦合必须单独处理

1. `simulation/sim.cpp::worldYear` 当前会重议 `world.mineOwner`，并据此增加宗门宝库。青石点正式接入时只能保留一个权属来源；不能同时保留旧随机归属和新占领归属，各自覆盖对方。关闭配置须继续走原路径与原随机顺序。
2. `adventure.cpp` 的后山探访是既有 7 天遗藏任务，不等于新长期经营点。首阶段保持此任务不变，不替换其资格、奖励或月额。
3. `location_services.cpp` 与日常采集依赖当前世界药材／灵核库存。资源点增益不能在关闭时仍加到这些旧库存，也不能把旧服务改成“占领才能使用”。
4. 兽潮、天机大比和多人系统不属于资源点第一版范围。不同模块的截止时间可以同时推进，但不得将资源点归属、收益或随机数写入兽潮积分和联机排行。

## 关闭行为契约

当前骨架比“有开关但照常运行后台模拟”更严格：没有新状态、钩子、动作路由或地图入口。配置关闭或误请求开启时，开发目录查询、能力查询及动作拒绝全部不触碰活动游戏。

未来模块关闭时必须保留以下结果与未接入模块的基线一致：

- 相同存档和种子、相同既有动作产生相同完整 `Game` JSON；时间、共享 RNG、世界资源、NPC 轨迹与纪事不因模块改变。
- 原 HTTP 路径、旧状态字段、地图地点、旅行时间、坊市报价、采药／后山／宗门资格完全继续走原公共入口。
- 不创建或加载补齐资源点世界，不争夺，不发奖，不扣维护费，不触发自动保存。
- 只读能力字段是附加应用元信息，不是角色状态；不注册能改变游戏的资源点 route。
- 就绪闸门未通过时，无论部署者如何请求启用，始终明确 `unavailable`，不能只靠隐藏按钮防止调用。

## 分阶段实施与验收

| 阶段 | 产物 | 开放条件 |
| --- | --- | --- |
| 0，本轮 | 配置、固定关闭就绪闸门、强 ID、内部目录、拒绝入口、方案和零副作用测试 | 不开放玩法、不显示入口；误启用仍不可用 |
| 1，离线规则 | 权属状态机、规则表、报价、独立账本、纯规则测试 | 仅核心夹具；默认部署关闭 |
| 2，隔离战斗 | 少量低阶点、两战斗节点、守卫快照、失败退出和重复结果处理 | 独立测试服及存档，不连现有线上账户 |
| 3，经营结算 | 月结、库存领取、NPC 争夺、关闭／恢复、完整 codec 与非法输入校验 | 开关关闭差分通过，开启闭环真实 API 和存读档通过 |
| 4，地图与城池 | 地图附加点位面板、宗门任务授权、城池经营权、青石权属单一来源 | 桌面浏览器可完整操作，现有地点服务不退化 |
| 5，发布 | 平衡数据、部署说明、回退路径、完整持续游玩测试 | 所有门槛满足才替换 `GameplayReady`；部署默认依然关闭 |

最低验收清单：

1. 默认关闭与请求开启骨架都无可见点和可执行动作；内部强 ID 解析不接受展示名、未知 ID 或地点 ID。
2. 所有查询及拒绝动作的整个序列化游戏完全相同；额外断言 RNG、天数和日志数量。
3. 将来用两份相同种子、相同存档执行旅行、购物、炼制、采集、后山、宗门、普通战斗、兽潮及跨年脚本，关闭模块与未接入基线完全一致。
4. 开启后的成功占领、守卫失效、敌对方抢先占领、退却、败北、重复提交、断开后恢复均有真实后果并只结算一次。
5. 月界与年界、库存上限、维护费不足、NPC 更换／死亡、长时间离线及禁用恢复不会重复收益或绕过资格。
6. 真实 HTTP 和浏览器验证应分别记录。核心夹具通过不能代替自然游玩，隐藏按钮也不能代替服务端闸门。

本轮测试入口为 `tests/test_resource_points.cpp::mfRunResourcePointTests`。测试只创建隔离角色并在内存中调用既有 `saveToJson`，没有读取、覆盖或新增玩家存档文件。
