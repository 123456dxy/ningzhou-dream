# 宁州一梦 C++20 编码规范

适用范围：本仓库的 C++20 核心、控制台、Web 服务及 C++ 测试。目标是提高可读性、明确模块职责、保证资源安全，并使声明、实现、调用方和外部协议保持一致。

“必须／禁止”是评审要求；“优先／建议”允许有理由的选择，应记录原因。本文是规范，不代表现有源码已经完成迁移或自动化建设。规范的制定不自动触发源码或工具配置迁移；后续修改和发布按独立任务执行。

## 1. 生效范围与迁移原则

- 新增 C++ 代码执行本文；旧代码按模块逐步迁移。命名修改与行为修改分开提交、分开评审和验证，禁止全仓库机械替换。
- 本文的大驼峰与 `mf` 规则替代旧开发约定中针对新增 C++ 符号的 `camelCase` 要求。现存 `nz`、`nz::content`、旧函数名等保留为有记录的兼容边界；不为一次调用而顺带重命名旧模块。
- 向现有模块新增接口时可沿用其旧命名空间边界，但新符号执行本文命名规则；命名空间迁移单独规划，不为改大小写平行复制一整套模块。
- 不把 C++ 命名规则传播为 HTTP 路径、JSON 字段、存档键、稳定业务 ID、文本模板参数、资源路径或前端符号的重命名要求。
- 示例中的 `Ningzhou::...` 与 `mf...` 展示目标写法，不表示仓库已有这些接口。标明“接口示意”的代码省略了领域定义，不能直接当作现成 API 使用；正反例也不是同一个可合并编译的程序。
- 目录与文件继续使用 `snake_case`。C++ 四空格缩进、附着大括号、UTF-8 无 BOM；参考根目录 `.editorconfig`、`.clang-format`。只格式化本次修改范围。

现有实现导航：[后端架构](BACKEND_ARCHITECTURE.md)、[C++ API 索引](CPP_API_INDEX.md)、[HTTP API 参考](HTTP_API_REFERENCE.md)。历史文档描述的是当时实现，不是扩散旧命名或旧耦合方式的依据。

## 2. 命名：统一形式，直接表达业务

### 2.1 符号规则

| 对象 | 规则 | 正例 |
| --- | --- | --- |
| 类、结构体、类型别名、模板类型参数 | 大驼峰 `PascalCase` | `StudyQuote`、`ManualId`、`ResultType` |
| 枚举类型与枚举项 | 大驼峰；业务枚举使用 `enum class` | `ActionKind::StudyManual` |
| 命名空间 | 每一级大驼峰，使用明确模块名称 | `Ningzhou::Progression` |
| 局部变量、参数、结构化绑定、捕获别名 | 大驼峰 | `RemainingDays`、`SelectedManual` |
| 成员变量、静态变量、常量 | 大驼峰，不加 `m_`、`g_` 或尾下划线 | `PlayerState`、`MaxPillCountPerBatch` |
| 成员函数，包括静态成员函数 | 大驼峰，不加 `mf` | `GetSpiritStoneBalance()`、`Create()`、`RequestStop()` |
| 命名空间级模块功能函数 | 小写 `mf` 加大驼峰业务名称 | `mfQuoteManualStudy()`、`mfApplyNpcPill()` |
| 匿名命名空间、`static`、`friend` 自由函数 | 同样使用 `mf` 加大驼峰 | `mfValidateStudyRequest()` |
| 布尔变量／查询 | 在上述规则内表达肯定条件 | `IsRunning`、`HasPendingBattle`、`mfCanStartManualStudy()` |

“大驼峰”指各单词首字母大写。已有通用术语写成 `Http`、`Json`、`Npc`、`Id`，不形成整段大写串。可在模块词汇表中解释通用术语，但不得用自造缩写代替业务含义。

禁止 `Tmp`、`Val`、`Obj`、`Cfg`、`Mgr`、`DoIt`、`Process`、`HandleData` 等缺少业务含义的命名。仅改成大写开头并不合规。循环变量也使用 `RecipeIndex`、`PillCount`，而非 `i`、`n`。`Manager`、`Helper`、`Utils` 不能代替具体职责。

`mf` 表示模块自由函数，不表示“会修改状态”。查询和命令都使用此前缀，副作用由业务名称、类型和契约区分。不得通过改成静态成员函数来规避模块设计。

### 2.2 数量、时间与常量

- 数量注明所数对象：`PillCount`、`CompletedRequestCount`、`CostSpiritStoneCount`。
- 时间注明单位：`StudyDurationDays`、`TimeoutMilliseconds`、`CooldownTurns`；优先用 `std::chrono` 强化时间类型，现实时间与游戏日历分开。
- 明确字节、概率、百分数及其他计量：`SaveSizeBytes`、`SuccessProbability`（0～1）、`HealthPercent`（0～100）。层数、品阶和索引注明起点及合法区间。
- 类型表达单位后，公共接口与变量名仍须易读。单位转换集中在边界，写明舍入、截断、饱和及溢出处理。
- 固定业务数值使用具名 `constexpr` 常量，可调平衡参数放具名配置并校验。禁止多个模块重复硬编码同一公式或常量。

```cpp
// 反例：首字母大写仍不能弥补含义模糊。
int mfCalc(int N, int T);
double V = 1.2;

// 正例：可直接理解参数含义与单位。
namespace Ningzhou::Progression {
inline constexpr double ManualCostPerLevelMultiplier = 1.2;
inline constexpr double ManualCostPerTierMultiplier = 2.0;

struct StudyQuote {
    std::chrono::days StudyDurationDays{0};
    std::int64_t CostSpiritStoneCount{0};
};
}
```

零报价是合法的数值对象，不代表允许开工；资格由独立结果表达。不得通过“费用是否非零”猜测执行资格。

### 2.3 必要例外

语言和外部契约规定的名称保持原样：

1. `main`、`wmain`、构造／析构函数、`operator...` 及编译器、平台要求的固定符号。
2. 标准库和第三方已有名称；覆盖其虚函数或实现规定的定制点、ADL、范围遍历契约时，使用契约要求的名称，例如确有必要的 `begin`／`end`。
3. 已有公共 C++ 接口、导出符号及旧命名空间：使用薄适配层委托新实现，记录原因、替代入口、调用方和移除条件，不复制业务规则。

例外精确到符号或必要的一组接口。“作为回调”“使用 `extern "C"`”本身不构成豁免。不得整目录关闭命名检查。业务常量和业务逻辑不使用宏；平台、构建和第三方要求的既有宏保留原名。

## 3. 模块与 namespace：职责先于文件位置

`namespace` 表达功能归属，不表达资源所有权或线程安全。公共接口统一声明，私有实现按稳定职责拆分，不按行数机械拆文件，也不为每个文件增加一层命名空间。

| 当前模块／入口 | 职责边界 | 禁止事项 |
| --- | --- | --- |
| `content` | 标识注册、边界解析、兼容映射、展示词表 | 扣资源或决定领域结算 |
| `foundation` | 通用数值、JSON 机制、基础工具 | 混入丹药、门派、账号会话规则 |
| `progression` | 修炼、功法、悟道、天赋、传承规则 | HTTP 解析、页面拼装、直接保存文件 |
| `crafting` | 制作、材料约束、统一报价与经济结算 | 让前端或工具库另算一套价格 |
| `combat` | 斗法状态机、效果、回合结算、只读意图 | 按展示文案识别技能，在查询中服丹 |
| `social` | NPC、宗门、交往、交易、适用丹药选择 | 绕过其他模块动作入口修改其私有状态 |
| `exploration` | 旅行、地图、地点、奇遇、秘境 | 自行绑定账号或改变 HTTP 访问策略 |
| `simulation` | 建角、时间、工作和世界动作编排 | 复制领域公式，把所有功能堆进主循环 |
| `persistence`／`save.cpp` | 编解码、校验、迁移、保存／加载编排 | 直接把未验证输入覆盖到活动游戏 |
| `interface`／`api.cpp` | 协议翻译、路由策略、领域调用、只读视图 | 隐藏状态补全、写档、复制规则 |
| `transport` 导航及 `http.cpp`、`pwhash.cpp` | 网络、传输、安全机制 | 判断角色资格、掉落或天赋效果 |
| `web_main.cpp`／控制台入口 | 应用组装、服务生命周期、边界错误处理 | 承载领域算法、发布短命对象的借用 |

当前 `model.h` 仍包含共享业务模型，不能整体视为纯工具；`progression/arts.cpp` 仍有制作等历史职责；部分传输与天机实现仍在 core 根。上述边界是维护要求，不声称现有依赖已经完全单向，也不要求本次移动文件。

公用工具库只提供可独立于本游戏解释和测试的能力。通用随机机制可以下沉，但游戏 RNG 状态归对应游戏所有；固定种子及随机序列属于需要维护的行为。

### 3.1 声明与实现组织

- 每个公共接口有唯一权威声明，放模块公共头；实现包含自己的声明头。禁止调用方手抄签名或包含 `.cpp`。
- 沿用 `core/*.h` 的兼容门面。内部协作头不自动成为公共 API；禁止跨模块包含 `persistence/internal.h` 等私有头。
- `.cpp` 按报价、校验、执行、编解码等职责拆分。仅本翻译单元使用的函数放匿名命名空间，仍执行 `mf` 命名规则。
- 头文件自包含，直接包含所需声明；公共头不写 `using namespace`。模板和必要内联实现留在头中，普通存储定义及非内联实现放 `.cpp`，遵守单一定义规则。
- 新依赖说明调用方向。循环依赖通过抽取契约、值对象或应用层编排解决，不靠暴露内部容器、随意增加 `friend` 掩盖。
- 共享结构的字段即使是 `public`，也不代表任意模块都有写权限。声明状态拥有者和动作入口；其他模块读快照或通过接口请求修改。

### 3.2 类型职责卡

每个类／结构体说明所属模块、抽象对象、职责边界、资源所有权、不变量和线程条件。公共类型在声明旁说明，内部类型可在模块文档集中列出。

```text
类型：ManualStudyService
模块：Progression
抽象对象：一场游戏中的功法研习服务
负责：资格验证、统一报价、提交研习安排
不负责：HTTP、展示文案、保存文件、其他领域的独立状态修改
拥有：不可变规则配置或有明确生命周期的配置快照
借用：仅调用期间借用游戏状态，不保存调用方裸引用
不变量：每位玩家至多一个有效研习安排，费用与耗时成对冻结
线程条件：修改由所属游戏的串行执行上下文调用
生命周期：构造即有效，销毁不访问已经结束的游戏
```

简单值对象可注明“无外部资源、可复制快照”；不为填表而把简单数据包包装成服务类。

## 4. 状态所有者与合法初始化

- 游戏状态归游戏／会话所有者，内容目录归内容所有者，连接归服务或连接对象。通过参数表达依赖，不从可变全局变量偷偷取得当前玩家。
- 减少可变全局和单例。确需保留时记录唯一拥有者、初始化顺序、访问同步及销毁顺序；`const` 指针／静态局部变量不保证其指向的内容不可变。
- **声明**描述名字与契约，**存储定义**提供对象及合法初态，**运行期初始化**装入已校验配置或建立运行资源。三者职责分离，不等于先留下不可用的半成品。
- 对象构造完成就必须满足不变量。若“空／关闭”是合法默认状态，明确它能执行的操作；若没有合理默认状态，删除默认构造，通过必要参数或工厂创建。
- 成员使用默认成员初始化或构造初始化列表。禁止未初始化标量、悬空句柄、魔法哨兵组合及依赖调用方补齐字段的状态。
- 文件读取、连接、线程启动和依赖配置的行为不得藏在跨翻译单元的全局动态初始化中。由应用入口显式组装，按依赖逆序关闭。
- 不可变编译期参数可以使用 `inline constexpr`；`constinit` 只约束静态初始化时机，不表示不可变、线程安全或运行期配置已完成。

## 5. 工厂与分阶段生命周期

复杂初始化提取为具名构造辅助函数或工厂，完成校验、资源获取、依赖组装和不变量检查。成功只返回完整有效对象，失败自动释放已取得资源，不把半成品交给调用方。

```cpp
// 反例：容易漏步骤，异常时还可能泄漏。
auto* Session = new GameSession;
Session->SetRules(Rules);
Session->LoadPlayer(PlayerPath);
Session->InitInventory();
// 忘记 InitCalendar()，对象却已经对外可见。

// 正例：接口示意；成功指针非空且会话已经满足全部不变量。
using SessionCreateResult =
    std::variant<std::unique_ptr<GameSession>, SessionCreateError>;

[[nodiscard]] SessionCreateResult mfCreateGameSession(
    const ValidatedGameConfig& Config,
    const PlayerSnapshot& Player);
```

值语义足够时直接返回值，不为工厂额外堆分配。预期业务失败用具名错误，调用方必须处理。C++20 不提供 `std::expected`，不能把 C++23 类型当成本项目默认能力。

辅助函数处理可解释的子步骤，不泄露局部缓冲区、锁或半有效句柄。避免构造／析构期间调用可覆盖虚函数、发布 `this`，或启动会访问尚未完整对象的异步工作。

确需分阶段时，定义显式状态机及下列行为，禁止含糊的 `Init()` 协议：

| 操作／当前状态 | 成功行为 | 失败与重复调用 |
| --- | --- | --- |
| 构造 | 合法 `Closed`，无运行资源 | 构造失败不产生可见对象 |
| `Open()`，`Closed` | 临时取得资源，校验后整体进入 `Ready` | 释放候选资源，返回原因，保持 `Closed` |
| `Open()`，已打开 | 不重复获取资源 | 返回 `AlreadyOpen`，不暗中重配 |
| `Start()`，`Ready` | 启动一次，进入 `Running` | 失败保持 `Ready`；已有工作时拒绝重复启动 |
| `RequestStop()` | 发取消信号，唤醒等待，进入 `Stopping` | 重复调用安全，不产生新任务 |
| `Close()` | 取消、等待退出、释放资源，进入 `Closed` | 幂等；说明阻塞及错误反馈方式 |
| 析构 | 不抛异常地完成兜底清理 | 不遗留线程，不将异常抛出析构函数 |

还必须说明调用线程、等待责任人、是否允许重新打开、关闭后合法查询、关闭 IO 失败如何记录，以及未就绪操作的明确错误。构造即有效允许对象处于合法关闭状态，不允许缺少调用方无法发现的必要初始化。

## 6. 业务类型、稳定 ID 与数值

- 封闭且可穷举的业务分类使用 `enum class`，例如动作种类、战斗阶段、错误类别；新增枚举项时检查分支与兼容映射。
- 开放实体使用不同的强类型 ID，例如 `ManualId`、`RecipeId`、`NpcId`。`using ManualId = std::string` 不是强类型，不能防止混用。
- ID 由受控构造／解析建立合法性；格式合法与“当前目录中存在”分别校验。换目录或恢复旧档后仍可能需要重新验证引用。
- 内部规则按具名分类和 ID 判断，不按显示文案、资源路径、名称前缀或不稳定枚举序号判断。历史固定索引映射集中封装并测试，不得任意重排。

```cpp
// 反例：改文案或枚举顺序就改变业务、破坏存档。
if (Pill.Name == "聚甲丹") { /* 增加护盾 */ }
using ManualId = std::string;
SaveKind = static_cast<int>(BattleKind);

// 正例：实体标识和效果分类分别表达，未知输入有明确结果。
enum class PillEffectKind { Heal, OpeningShield, CultivationExperience };

// 接口示意：ManualId 是独立值类型，解析函数查询权威内容目录。
[[nodiscard]] std::optional<ManualId> mfParseManualId(
    std::string_view WireValue, const ManualCatalog& Catalog);

switch (Pill.EffectKind) {
case PillEffectKind::OpeningShield:
    // 调用统一开局护盾规则。
    break;
case PillEffectKind::Heal:
case PillEffectKind::CultivationExperience:
    // 由各自的具名效果实现处理。
    break;
}
```

业务标识字符串仅在 HTTP、存档、配置、内容文件和兼容适配边界解析／序列化，内部传递类型化值。强 ID 的私有存储可以是字符串；玩家姓名和展示文字也仍是文本，但不能用于业务分类。

未知分类、未知实体和非法别名明确失败。产品定义的旧档回退集中在版本化迁移中，不得无条件替换成第一个合法值。不要从任意输入整数直接 `static_cast` 得到枚举。

外部数值检查类型、整数性、范围、有限性、符号和溢出，先验证再进行乘法、指数和单位转换。JSON 的宽松默认转换不等于校验成功。数量／金额优先用范围足够的整数；浮点倍率明确精度、区间和舍入策略。

## 7. RAII、所有权与借用生命周期

- 文件、套接字、锁、线程、平台句柄、临时文件和订阅都由 RAII 对象管理。取得裸句柄后立即包装，检查无效值及释放配对。
- 优先值对象；需要动态多态或唯一资源所有者时使用 `unique_ptr`。仅在多个独立参与者共同延长生命周期时使用 `shared_ptr`，不能借此回避所有者设计。
- 共享图的反向观察边使用 `weak_ptr`，调用时 `lock()` 并处理对象已失效；这不会自动使其他裸借用安全。
- 裸指针表示可空借用，引用表示非空借用；迭代器、`span`、`string_view` 不拥有数据。声明来源、有效期、失效条件，不返回局部数据的借用。
- 检查扩容、删除、排序、整体替换、移动和热更新造成的失效。`const` 借用不延长生命周期，也不阻止另一个线程修改底层对象。
- 回调、异步工作、协程挂起、缓存不能持有短命栈对象的借用。按值捕获也须检查内部是否仍含裸指针／视图；捕获 `this` 必须证明拥有者活得足够久。
- 遵循 Rule of Zero；资源包装显式定义复制、移动、移动后合法状态。析构不抛异常，需要报告关闭／提交失败时提供显式操作。

```cpp
// 反例：视图指向已经销毁的字符串。
std::string_view mfReadPlayerName() {
    std::string PlayerName = "宁州修士";
    return PlayerName;
}

// 正例：调用方拥有返回值。
std::string mfReadPlayerName() {
    return "宁州修士";
}

// 反例：线程可能活得比调用栈更久。
std::thread([&PlayerSnapshot] { mfSaveSnapshot(PlayerSnapshot); }).detach();

// 正例：接口示意；任务拥有快照，外层负责取消和等待。
std::jthread SaveWorker(
    [Snapshot = std::move(PlayerSnapshot)](std::stop_token StopToken) {
        mfSaveSnapshotUntilStopped(Snapshot, StopToken);
    });
SaveWorker.request_stop();
SaveWorker.join();
```

标准库成员名保持原样。`request_stop()` 不会强制中断任意 IO；任务须响应取消并唤醒阻塞等待，保存任务只能在安全边界取消，不能破坏原文件。

调用返回内部工作区／`thread_local` 数据引用的旧接口时，确认下一次调用是否覆盖内容；需要跨调用保留时复制值。`thread_local` 不保证嵌套调用安全，也不替代共享状态同步。临时会话绑定、保存目录覆盖等作用域状态应由 RAII 恢复，不能依赖所有返回路径手动还原。

路径在内部使用 `std::filesystem::path`；Windows 命令行采用宽字符入口，在 UTF-8 协议边界显式转换。禁止把 UTF-8 字节串隐式当成本地代码页路径，也不能假设短路径全是 ASCII。编码与中文路径应纳入相关回归。

## 8. 并发、锁与退出

- 公共接口声明具体线程条件：线程限制、可重入、独立实例可并发、或须持有的锁。只写“线程安全”不够。
- 当前 API 动作依赖 transport 的串行调用约束，连接收发可以并发。不能把这误写成“进程单线程”，也不能未经评审并行执行领域动作。
- 原子操作仅用于独立计数和标志。余额、库存、工作安排、RNG、时钟等组合不变量，由同一所有者的锁或串行上下文整体保护。
- 仅作统计、不发布其他数据的原子计数可考虑 `memory_order_relaxed`；不能靠一个原子宣称其他普通字段已安全发布。优先清晰的锁，不自行设计无锁复合状态。
- 锁使用 `lock_guard`、`scoped_lock`、`unique_lock` 等 RAII 包装。说明锁顺序；条件等待带谓词并考虑虚假唤醒与取消。
- 不在状态锁内执行未知回调、长时间 IO，或等待需要同一锁的线程结束。锁外计算使用快照，提交前校验版本，防止覆盖并发变化。
- 每个线程有所有者、取消入口、唤醒方式和等待责任人；禁止默认 `detach()`，避免线程等待自身结束。
- 关闭顺序为停止接收新任务 → 取消并唤醒 → 等待工作结束 → 释放依赖资源。`jthread` 的析构不能代替退出顺序设计。

```cpp
// 反例：两个原子并不构成一笔原子交易。
SpiritStoneCount.fetch_sub(CostSpiritStoneCount);
PillCount.fetch_add(PurchasedPillCount);

// 正例：接口示意；锁覆盖最终校验与整体提交。
{
    const std::scoped_lock Lock(InventoryMutex);
    mfValidateAndCommitPurchase(InventoryState, PurchaseRequest);
}
```

- 完整句子放词表，用文本 ID 和具名参数渲染，避免重复硬编码和零碎拼接。

Message = "参悟" + ManualName + "消耗" + std::to_string(SpentDays) + "天";

## 10. 公共接口契约与失败保证

每个公共函数及成员操作说明用途和下列契约。简单访问器可以简短，但不省略借用或线程风险。

| 项目 | 必须说明 |
| --- | --- |
| 参数 | 范围、单位、可空性、所有权／借用期、前置状态、别名限制 |
| 返回值 | 成功条件、单位、所有权、失效条件，零／空的含义 |
| 错误 | 预期业务错误、可能异常、传播方式、重试及重复调用语义 |
| 副作用 | 修改范围、资源／RNG／时间消耗、IO、回调 |
| 失败保证 | 所属事务中哪些状态必须保持不变，提交边界 |
| 线程／阻塞 | 调用线程、锁要求、可重入性、等待、取消 |

```cpp
// 接口示意：类型和错误均为模块公共契约。
/**
 * 用途：查询指定功法下一层的耗时与灵石报价。
 * 参数：Player 为稳定只读快照；Manual 必须存在于 Config 的目录。
 * 返回：StudyQuote，单位为游戏天和灵石枚数；或具名 StudyError。
 * 错误：未知功法、非法配置、已满层明确失败，不用零报价表示失败。
 * 副作用：无；不补全角色，不推进 RNG／日历，不写存档。
 * 线程：快照和配置均不可变时可并行；const 引用不保护并发写入。
 * 阻塞：无 IO，不保存参数引用；分配异常按应用边界策略传播。
 */
[[nodiscard]] std::variant<StudyQuote, StudyError> mfQuoteManualStudy(
    const PlayerSnapshot& Player,
    const Content::ManualId& Manual,
    const StudyConfig& Config);
```

- 查询不得隐式初始化活动状态、服丹、推进活动游戏或共享 RNG、推进真实日历、写档或绑定账号。准备状态使用独立具名命令，由真实动作边界调用。
- 建角／战斗预演可以在固定种子或克隆状态的局部副本上进行隔离演算，包括推进副本 RNG；不得把副本的 RNG、时钟或资源变化提交回活动状态，也不得修改外部文件。相同快照、种子和配置应产生相同预演结果。
- 命令名说明变化，例如 `mfStartManualStudy`。资格、报价和执行共用权威规则；实际执行前重新校验。
- 预期业务拒绝使用具名错误；`optional` 仅用于无需细分原因的未找到／未解析。需要解释原因时不能只返回 `false` 或空字符串。
- 只捕获能恢复、转换边界或补上下文的异常，禁止空 `catch`。`assert` 不代替外部输入校验，`noexcept` 必须有依据。
- 关键校验、保存、启动、提交结果加 `[[nodiscard]]`。日志不输出凭证或完整私人存档。

### 10.1 失败不得留下部分结果

采用“解析 → 全部校验 → 候选结果 → 一次提交”。这里的失败指校验拒绝、执行前置条件不满足或未提交的技术失败，必须保持所属事务内的余额、库存、任务、时间、RNG 和相关计数不变。

炼丹未成、突破未成等是已经执行并提交的游戏判定结果，可以按明确规则扣材料、灵石、时间并推进 RNG。接口必须区分“动作没有执行”与“动作已执行但判定未成功”，不能将后者当作可无损重试的请求错误，也不能借此放宽真正拒绝路径的原子性。

```cpp
// 反例：容量不足时已经扣费。
Player.SpiritStoneBalance -= RequiredSpiritStoneCount;
if (!mfHasPillCapacity(Player)) {
    return PurchaseError::InventoryFull;
}

// 正例：接口示意，提交自身也不得在中途失败。
auto Candidate = mfBuildPurchaseCandidate(CurrentState, Request);
if (const auto* Error = std::get_if<PurchaseError>(&Candidate)) {
    return *Error;
}
mfCommitPurchase(CurrentState, std::get<ValidatedPurchase>(Candidate));
```

候选状态包含关联 RNG，不能只回滚金额。使用不抛异常的整体交换、替换或有明确回滚保证的提交，不能假设任意赋值都不会失败。

文件保存采用同目录临时文件、完整写入校验和平台支持的替换流程，保留失败前有效文件。内存提交、文件、网络回复和回调分别说明事务与恢复边界：例如动作已提交但自动保存失败，应返回“动作成功＋保存失败信息”，不能报告为动作未执行而诱导重试。非幂等动作定义请求去重／幂等规则，丢失或重复回复不得二次扣费。不能宣称跨系统天然原子。

### 14.2 建议逐步建设的门禁

1. **格式**：固定工具版本，仅对变更文件运行格式检查，不把全仓重排混入功能提交。
2. **AST 命名**：评估 `clang-tidy` 标识符命名检查或专用 AST 规则。区分类、枚举、命名空间、变量、常量、成员、静态成员和自由函数；自由函数要求 `mf`。用正反样本覆盖匿名命名空间、模板、重载、回调、运算符、第三方覆盖和兼容适配。不得把“所有函数加 mf”应用到成员函数。
3. **精确例外**：按符号登记原因、替代入口和移除条件，不整目录忽略。自动化检查形式，业务名称是否准确仍由评审判断。
4. **依赖边界**：建立模块允许依赖和私有头清单，历史耦合作为基线，阻止新增跨模块私有 include；结合头文件自包含编译及依赖图。
5. **资源与并发检测**：按工具链支持启用静态分析、AddressSanitizer／UndefinedBehaviorSanitizer；在支持的平台单独配置 ThreadSanitizer。不假设检测器可同时启用，也不假设 MSVC、MinGW、Linux 支持相同。
6. **契约与兼容**：维护旧档样本、路由／字段／别名清单、ID 往返和未知值用例；补只读状态／RNG／文件不变、失败原子性、重复操作、取消、词表整表替换测试。
7. **分层执行**：先快速命名／格式／依赖检查，再构建与定向回归，按风险运行完整 CTest、HTTP、浏览器检查。输出版本、命令、范围、失败原因，明确未执行项。

Clang 系分析必须使用准确编译参数。需要 `compile_commands.json` 时，选择支持导出数据库的 CMake 生成器和匹配工具链，不能假定 Visual Studio 生成器已经提供。配置尚未落地前，不能把建议写成现有保证。

新增 C++ 测试仍接入 `tests/harness.h`、`tests/test_main.cpp`；新增／删除源码时按需运行 `python tools/generate-vs-projects.py` 同步静态 VS 工程。只修改规范文档时核对内容、链接和变更范围即可，不借机构建或重构源码。
