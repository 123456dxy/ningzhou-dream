# 炼丹炼器时长与坊市预算

## 当前规则

时长在 `src/core/crafting/craft_timing.h/.cpp` 集中定义。外部协议与公共 C++ 入口仍使用既有 `brew`、`forge` 和 `ecoCraftDays`，由薄适配转换为 `CraftKind`；未知类型明确返回无效，不默认为炼器。

| 品阶 | 炼丹每炉基础天数 | 炼器每件基础天数 |
| --- | ---: | ---: |
| 一 | 4 | 30 |
| 二 | 5 | 60 |
| 三 | 6 | 120 |
| 四 | 7 | 240 |
| 五 | 8 | 480 |
| 六 | 9 | 当前无六阶炼器配方 |

炼丹一品每炉四天，此后每升一品每炉多一天；炼器一阶一个月，此后每阶翻倍。世界历每月 30 天、每年 360 天。

保留既有能力与生活减时：

- 炼丹能力使用丹术，炼器使用器道累计经验除以 10。能力减时为 `min(30%, sqrt(能力) × 0.016)`。
- 炼器再乘 `1 − forgeSpeed`；功法、器道和百炼匠心共用已有 `talentMods`，生活减时最高 60%。该乘区不影响炼丹。
- 完成以上乘算后向上取整，最少一天；一品丹满丹术减时后为三天。
- 批量炼丹只允许 1、3、5、10 炉，总时长为每炉最终天数乘炉数。炼器仍一次一件。代炼与代铸使用同一规则。
- 没有新增成功率、炉费、产量、材料或耐久算法；这些继续由各自权威规则计算。

## 工作与旧存档

实际开工仍通过 `ecoActionInfo` → `ecoActionError` → `ecoBegin`。工坊丹方列表、炼器预览、真实 `/api/craft`、`/api/forge` 和 `/api/eco` 都消费同一 `ecoCraftDays` 结果。`ecoBegin` 把报价冻结到既有 `Job.total`、`Job.remaining`，随后日历仅扣实际过去的天数。

读档不重算正在进行的工作；旧版本的 100 天合同仍保留总 100 天及当前剩余时间。开工后提高丹术、器道或改变天赋也不改写已经投入的工作。新规则只用于下一次开工，不新增存档字段。

历史 `play::craftDo` 与 `artAnnual` 是即时结算兼容入口，没有当前制作 HTTP 路由调用；本次保留其既有时间语义，不把新日历推进混入旧收益函数。

## 坊市三年收购资金

规则集中在 `src/core/crafting/market_cycle.h/.cpp`，世界历每三年（1080日）刷新一次。原有月预算算法只作为预算底座，不再用于每月发钱：

```text
原月预算 = min(十亿, max(声望基础额度, 可炼单枚丹药收购价, 同阶标准法器收购价) × 3 × 大境界倍率)
三年预算 = min(十亿, 原月预算 × 50)
大境界倍率 = 炼气1 / 筑基2 / 金丹4 / 元婴8 / 化神16
```

声望底座保持 `min(2400, 400 + max(0, 声望) × 8)`；材料成本定价、声望议价、自炼加成继续生效。金额使用64位中间值并饱和到持久化上限十亿。常价、无声望的初期三年预算依次为72000/324000/1152000/3600000/10368000灵石。

真实出售仍从 `economy.marketCash` 扣款。每月同类出售件数限制取消，单次售尽只受持有数量、本期资金与角色灵石容量限制。旧 `sold` 账不再参与资格或累加，避免历史计数溢出。

`MarketCycleIndex` 记录已兑付账期。`ecoRefresh` 在真实日历达到1080日倍数时刷新一次；同一账期内换月、晋阶、提高声望、换城、查询和读档都不补款。月度任务与订单继续按月更新。旧档缺少账期字段时从既有经济月份推导，保留剩余资金，禁止读档重领。

状态输出 `marketRefreshCycleDays`、`marketDaysUntilRefresh`、`marketSaleCountUnlimited`；`pricing.market` 输出 `refreshCycleDays`、`daysUntilRefresh`、`nextCycleBudget`。历史 `nextMonthBudget` 等字段仅为接口兼容别名，值现为下一三年周期预算，桌面显示使用新字段。

## 定向检查入口

- `test_craft_timing.cpp::mfRunCraftTimingTests`：逐阶基数、减时、批量与真实Job、代炼、旧合同、境界预算与换月不充值。
- `test_market_cycle.cpp::mfRunMarketCycleTests`：1080日边界与重复刷新、五境界50倍、严格账期输入、旧档余额保持、真实百枚售丹与每年2点自然化毒。
- `test_potion_bulk_sales.cpp::mfRunPotionBulkSalesTests`：售尽数量、资金不足、拒绝原子性、溢出边界。

本说明列出测试入口，不代替本轮实际运行记录。实际检查与可执行文件信息见本轮交付记录。
