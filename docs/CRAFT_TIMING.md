# 炼丹炼器时长与坊市预算

## 当前规则

时长在 `src/core/crafting/craft_timing.h/.cpp` 集中定义。外部协议与公共 C++ 入口仍使用既有 `brew`、`forge` 和 `ecoCraftDays`，由薄适配转换为 `CraftKind`；未知类型明确返回无效，不默认为炼器。

| 品阶 | 炼丹每炉基础天数 | 炼器每件基础天数 |
| --- | ---: | ---: |
| 一 | 4 | 30 |
| 二 | 5 | 60 |
| 三 | 6 | 120 |
| 四 | 7 | 240 |
| 五 | 8 | 480 |
| 六 | 9 | 当前无六阶炼器配方 |

炼丹一品每炉四天，此后每升一品每炉多一天；炼器一阶一个月，此后每阶翻倍。世界历每月 30 天、每年 360 天。

保留既有能力与生活减时：

- 炼丹能力使用丹术，炼器使用器道累计经验除以 10。能力减时为 `min(30%, sqrt(能力) × 0.016)`。
- 炼器再乘 `1 − forgeSpeed`；功法、器道和百炼匠心共用已有 `talentMods`，生活减时最高 60%。该乘区不影响炼丹。
- 完成以上乘算后向上取整，最少一天；一品丹满丹术减时后为三天。
- 批量炼丹只允许 1、3、5、10 炉，总时长为每炉最终天数乘炉数。炼器仍一次一件。代炼与代铸使用同一规则。
- 没有新增成功率、炉费、产量、材料或耐久算法；这些继续由各自权威规则计算。

## 工作与旧存档

实际开工仍通过 `ecoActionInfo` → `ecoActionError` → `ecoBegin`。工坊丹方列表、炼器预览、真实 `/api/craft`、`/api/forge` 和 `/api/eco` 都消费同一 `ecoCraftDays` 结果。`ecoBegin` 把报价冻结到既有 `Job.total`、`Job.remaining`，随后日历仅扣实际过去的天数。

读档不重算正在进行的工作；旧版本的 100 天合同仍保留总 100 天及当前剩余时间。开工后提高丹术、器道或改变天赋也不改写已经投入的工作。新规则只用于下一次开工，不新增存档字段。

历史 `play::craftDo` 与 `artAnnual` 是即时结算兼容入口，没有当前制作 HTTP 路由调用；本次保留其既有时间语义，不把新日历推进混入旧收益函数。

## 坊市月度收购资金

统一公式：

```text
原预算底座 = max(声望基础额度, 当前收购层级最高单枚丹药的实际收购价)
月度预算 = min(1,000,000,000, 原预算底座 × 基础三倍 × 大境界倍率)
```

| 大境界 | 乘区 | 可收购丹药市场层级 |
| --- | ---: | --- |
| 炼气 | 1 | 一品 |
| 筑基 | 2 | 一至二品 |
| 金丹 | 4 | 一至三品 |
| 元婴 | 8 | 一至四品 |
| 化神 | 16 | 一至六品 |

声望底座仍为 `min(2400, 400 + max(0, 声望) × 8)`；完整原预算底座先翻三倍，再叠加境界乘区。例：高声望炼气底座2400，预算7200；筑基为其当前原底座六倍，化神为其当前原底座四十八倍。计算时先钳位已封顶的声望，避免异常大整数乘法溢出。大境界乘区位于完整原预算外侧，既保留朋友提交的整枚高价丹可变现保护，也增加高境界修士每月总收购资金。各小境界不额外倍增，异常境界指数钳位到 0～4；金额使用 64 位乘法后饱和到十亿。

`ecoMarketBudget` 为只读下一期预算，不是本月余额。初始化与真正跨入下一月时 `ensureEconomy` / `ecoRefresh` 才补充预算；真实收购从 `economy.marketCash` 扣款。查询、同月突破、声望变化、重复刷新和存读档不会给已花掉的资金充值。物品同类月出售件数限制不变。

状态视图保留 `marketCash`、`marketBudget`、`marketTier`，增加只读 `marketRealmMultiplier` 与 `marketBudgetRule`；声望视图 `marketCashCap` 继续输出同一预算。前端不重新计算。
