# 兽潮战期、金榜与战后坊市实施设计

目标：把现有随机长兽潮升级成可预测的短期讨伐活动，并让角色构筑、战场选择和战后收益形成完整玩法。

数值：统一规则表管理60天战期、30天市场、四战场最低境界0/3/6/9及每杀1/3/9/27分。一般修士每天随机0–1杀，具有效完整流派的特殊修士0–2杀。金榜同分并列；奖励按参加时境界的标准月俸冻结，至少一杀才有保底3年，前十/前三/第一分别10/20/30年。排名购价基于当前声望、天赋和行情下的正常坊市购入价，最低不得少于该正常价的五折。

模块：simulation/tide负责场次、期限、日积分与幂等结算；tide_market负责一次性库存生成、报价和原子购买；content/npc_combat_profiles提供稳定构筑ID与实际战斗配置。model只存事实；接口视图统一生成；桌面UI只消费权威数据。

时间：成功完整回合耗一天，首轮出牌击杀与成功撤离也耗一天，非法操作不耗时。先记录末日战果，再推进世界日历，最后结算。到期尚未完成的对局撤出且不发击杀积分。普通斗法与天机对局不计此时间。不能持有Battle/Npc引用跨越世界年度更新或人生结束。

兼容：保留active/monthsLeft等旧字段；旧活跃活动按加载当日迁移为60天短战期，不凭旧纪事文本推算积分；旧非活跃档不补发奖。场次、积分、已发奖励与有限市场库存完整持久化；读状态、报价和载入现代存档不重新抽签、不刷新库存或重复发奖。

实施顺序：

1. 已用旧二进制复现RED：固定60天=false，完整回合推进一天=false。
2. 增加共享模型/接口；并行实现活动规则、桌面UI及独立存档codec。
3. 接通战时公共日推进、战果来源和单一tide视图/市场购买路由。
4. 测试直接击杀、末日击杀、DOT结束、撤离、跨年寿尽、并列榜单、读档幂等、库存/余额不足与假报价失败原子性。
5. 全量规则/API回归、桌面真实DOM与MSVC构建；同步可迁移VS项目与中文维护文档。

边界：不调整多人天机业务或手机UI，不修改玩家真实存档，不自动重启8107或部署服务器。保留工作区并发修改的release文件。用户已要求本次完成后提交并推送GitHub；使用既有后端与电脑端UI分支，提交备注列出最终更新内容。
