# 掌中山河：手机端独立试行前端 v2

署名：小白（gpt-dot）
基线：`68357de06e73f3a8e79d362c5b5423f9cfaf7ede`
工作分支：`dot/mobile-frontend-v2`

## 入口与回退

**最新范围（2026-10-12）：只改手机端，PC 端暂时不动。**

- 手机试行入口：同一个宁州 C++ 服务的 `/v2.html`，由使用者主动打开。
- PC 继续使用原来的 `/` 或 `/index.html`；不得用 v2 替换电脑端首页、样式或导航。
- 不添加自动设备跳转，不把手机试行入口自动设为任何设备的默认首页。若以后调整入口，须另行确认。
- 经典版全部原始前端文件保持不变。本轮逐字节核对了基线中 `web/` 的 84 个已跟踪文件，全部一致；`web/` 下新增文件仅位于 `web/v2.html` 与 `web/v2/`。
- 两个界面使用同源 `/api/`、同一会话 Cookie 与同一服务端存档。无需迁移玩家数据。
- 新版菜单、登录页和设置页均保留明确的“经典界面”入口。
- 经用户追加授权，补齐 C++ 的展示字段与同源资格/费用检查；不修改规则表、既有数值或存档格式。不引入前端运行时依赖，不改变默认首页。
- 后端由手机端与 PC 经典界面共用：新增字段、丹药说明与丹毒消散时间等展示修正也会通过原 API 返回给经典版，可能改善其显示文字或数字。原前端文件不变不等于旧 API 输出完全相同；规则与存档兼容性由下述差分测试验证。
- 初版独立前端回滚点：`ad6fb7cf736ca1d0f8dc443795d86bcd27603f60`。本轮在其上追加信息架构与引擎展示契约，不覆盖该提交。
- 本次未部署、未切换线上入口。若只采用经典版，无需任何数据回滚。

已有构建时运行：

```sh
./build-v2/ningzhou_web --host 127.0.0.1 --port 8106 --web "$PWD/web" --data /path/to/game-data --no-open
# 手机试行：打开 http://127.0.0.1:8106/v2.html
# PC 保留：http://127.0.0.1:8106/ 或 /index.html
```

如需构建，按仓库原有 CMake 流程生成 `ningzhou_web`；可执行文件位置随构建目录变化。打包同步 `web/` 时会自然包含手机试行文件，但不得因此改变 PC 的入口或自动路由。

## 结构

| 文件 | 职责 |
| --- | --- |
| `web/v2.html` | 独立入口，不加载旧 app 或旧 CSS 补丁 |
| `web/v2/api.mjs` | 同源请求、超时、全局写操作互斥、天机请求编号及恢复 |
| `web/v2/store.mjs` | 唯一服务端状态、查询缓存、界面偏好 |
| `web/v2/router.mjs` | 五个主目的地及可恢复的子路由 |
| `web/v2/ui.mjs` | 文本转义、按钮、页签、面板、服务端数值预览 |
| `web/v2/app.mjs` | 登录、建号、控制器、查询生命周期、抽屉/弹层、存档 |
| `web/v2/eligibility.mjs` / `outcomes.mjs` / `disclosures.mjs` | 全局可见状态守卫、权威前后差值回执、展开态保护 |
| `web/v2/views/*.mjs` | 无网络副作用的页面渲染器 |
| `web/v2/styles.css` / `player-mobile.css` / `battle-mobile.css` | 独立的纸色/墨色/青玉设计、手机操作工作区与固定战斗视口，不叠加旧样式 |

仅复用项目已有插画及 `web/cards.mjs` 的纯展示语义函数。界面不计算伤害、突破成功率、旅行收费、炼器结果或建号预算；读取引擎下发的预览与条件。折算显示百分比、进度条与数量差值不改变游戏规则。

五个主目的地为：修行、山河、行囊、道法、世间。功能在各自页内分组；普通斗法、秘境探索、待决抉择与人生结局优先于普通导航。手机地图用原地目的地选择和有意打开的筛选抽屉，选定地点和行动直接展示。战报与大量不可用目录默认折叠。

## 第二轮信息架构与权威展示字段

- 首页常显资质、悟性、修为/经验与引擎普通斗法开局 HP/上限；健康百分比仅在“人物详情”中展示。非战斗参考不借用天机冻结数据。
- 行囊默认持有物品，分类/搜索/数量/用途同位。丹药展示当前人物实际效果、耐药与丹毒变化、可服用条件；装备展示配装、实际成本、回收金额与禁用原因，销毁/出售二次确认。坊市默认买得起。
- 道法默认当前配装；功法按已学/可修习/实际已知来源组织，神通按已学/携带/当前可获取筛选，可用老师和藏经阁直接相连。大道只展开选中一道；服务端即时数值优先，完整试算背景折叠。
- 各页保留“上次操作结果”摘要及完整回执；只比较服务端前后状态，不推算奖励公式。展开态在查询/写操作更新后保持。人物与物品搜索使用短防抖。工作区更新时可短暂保留只供显示的上次查询快照，相关动作锁定，直到新条件返回；旧快照不会被当作新资格缓存。
- 地图服务的 `targetTab` 映射真实目的地；手机地点选择支持名称/类型/危险值筛选。兽潮从首页直达实际面板；“固守”只写日志、不推进时间，明确显示这一事实。
- 突破展示服务端资格、禁止原因、耗时、失败损失比例及自动使用的准备物。结局区分本世结算与累计传承，先展示奖励回执再开下一世；明确放弃收获另需确认。存档位覆盖需确认；存档写入警告持续保留至保存成功。

后端追加与共享检查主要涉及 `src/core/api.cpp`、`arts.{cpp,h}`、`battle.{cpp,h}`、`calendar.{cpp,h}`、`play.cpp`、`roster.cpp`、`shop.{cpp,h}`，并增加 `tests/test_display_contract.cpp`：

- `pillCatalog` 提供全部丹药的当前药效、服用资格、耐药、丹毒预览；坊市/丹方说明来自同一规则来源。真实服丹动作复用同一计算计划。
- `player.combatReference` 提供普通斗法开局 HP/上限、灵力/容量/回灵、护盾、剑气、减伤与遁速；健康度单位单独明确。
- `breakthrough` 增加完整 enabled/reason、days、failureLoss 与准备物消耗；`ending.settled` 使用已有传承领取记录。
- 装备 `actions` 与 `furnaceRepair` 提供同源资格、costStones/returnStones。丹毒消散时间展示改为复用真实日常消散速度；不改消散规则。

仍有边界：野外悬赏入场费、远方道友邀请费尚未以数值下发，不能当成免费；新版明确标明未报价，阻断该动作并提供经典入口；不再确认未知扣费。后山探访暂从经典入口进入。丹方完整原料清单/批次总报价、精确战后结构化奖励回执尚未全量提供；当前显示真实已有说明、禁用原因及权威状态差值。这里不声称所有历史功能已迁完。

## 并发、恢复与安全

- 单一写锁覆盖普通游戏与天机动作，避免重复点击并行提交。
- 普通写操作在断网/超时后不重试；先重新读取服务器进度。核对未成功时保留界面写锁。
- 天机写入使用 `requestId`，仅同一账号可重试同一待确认请求。请求保存于 sessionStorage，不保存密码、Cookie 或访问令牌。
- 天机状态足以证明旧请求已生效时解除待确认状态；其他情况使用原请求编号重试。
- 401 不自动跨账号重做动作。重新登录后恢复服务端状态，玩家自行重新确认动作。
- 查询同时检查账号、状态代数、操作代数、每个查询键的最新请求及 NPC 身份。旧失败响应也不能覆盖新账号；炼器旧预览不能覆盖新选材。
- 新角色/读取/导入清除旧查询数据；切换账号清除界面草稿及选中的 NPC。
- 所有玩家姓名、日志、服务端文本和属性值经过 HTML 转义。模块不覆盖全局 fetch。

## 第三轮：手机操作闭环修订

用户后续明确指出：百分比血量、首页看不到经验、出牌及切换日常反复纵向翻页，仍不符合实际操作习惯。因此第三轮不把“首屏露出一个按钮”当作验收，而验证选择、执行、结果之后的控件位置是否稳定。

- 手机 v2 使用固定视口外壳，顶部状态和底部导航不参与文档滚动；主内容及有意打开的长列表独立滚动。PC 原 84 个前端文件与入口不变。
- 首页是一个固定操作台：真实 HP/上限（注明普通斗法开局参考）、修为/所需、资质悟性、原地计划选择与1天/30天/1年/10年推进按钮同屏。10年按引擎历法为3600天，保留默认遇事暂停。计划预览固定两行；有任务时选择只影响任务之后的日常，不中止任务。回执预留固定摘要位，完整结果打开覆盖层；其他事务独立滚动。
- 普通与天机斗法均为独立全屏战斗工作区：双方 HP、意图/状态、最新结果、横向手牌、灵力与结束回合固定在各自区域；卡牌全文、法宝、移除目标、战报和退出使用覆盖层。关闭后恢复手牌横向位置，不要求上下找按钮。
- 行囊、坊市、功法、神通、悟道、工坊改为选择一个对象的工作区，不再默认铺开每一张完整卡片。数量、效果、风险、费用、动作与局部回执相邻；装备当前槽位与候选相邻比较。
- 地图目的地、路线或当地事务、报价、行动同位；旅行开始后原启程位置直接成为剩余天数的继续按钮，没有新增顶部任务大横幅。
- NPC 往来使用选人、选事项、选具体行动的局部工作区，当前好感/交情与费用和动作同位。动作变得不可用后保留已选 ID 和原因，不能自动跳到下一个可用动作。
- 默认选择稳定，动作前保存当前实体；读取新资格期间保留只读显示快照并锁动作，避免先清空再填回的布局跳动。详情展开与局部滚动位置保留。回执按提交时的路由和工作区隔离；已自动推进的炼丹以实际天数、剩余任务和新日志反馈，不复述接口固定的“已安排”措辞。
- 候选配给费用仍未全量下发：新版不直接提交未报价的配给变更，提供可用的经典入口。炼丹仅展示真实逐炉报价和缺料原因，不臆造尚未提供的完整材料清单或整批报价。
