# 正式筑基集成

玩家在炼气后期修为圆满时，自选五行凝练或周天冲穴。规则移植自 `prototypes/zhuji-lab` 的 elements 分支及 `prototypes/meridian-network-lab`，不包含旧三脉、回路或七穴原型。周天图保持36穴65边，包括丹田与至阳双向通路；界面不提供返程预算提示。

## 玩家操作

1. 在修为圆满后的突破入口打开筑基面板；经典手机版的快捷突破按钮定位到同一面板。选择五行凝练或周天冲穴，再选择库存中的筑基丹（凝元丹）和可选灵核，界面显示后端真实费用与资格。
2. 确认后扣除准备并推进90天安排。若途中遇事或斗法，先完成当前中断，再接续原安排；完成后界面进入筑基玩法。刷新或存读档会接续当前局面。
3. 五行先选术式，再点五行施展；调息先选来源、再选目标，跨轮余气超限时输入保留量。周天先点穴位查看效果、耗气与成功率，再确认冲穴；选穴预览不扣气。两者通用规则和修行手记均可展开查看。
4. 达到定型条件后确认永久结果。成功分数超过100的部分增加基础气血；成功后从结果面板前往神通界面的单一本命槽，随时在空闲时选择或更换本命。失败或主动收功可以重新准备，已扣物资与过去时间不退。

本轮只新增炼气后期升筑基的玩法。金丹、元婴等后续境界仍从原突破入口使用既有规则，已筑基旧角色继续原人生，不补发根基或本命选择。

筑基交互当前由网页提供。控制台在炼气后期尝试突破时提示转往网页，不创建旧概率突破任务或扣准备；载入活跃筑基局后，仅保留查看内部状态、存读档和退出。准备中的既有安排可继续推进，激活玩法后立即停止；需要在网页端读取对应存档后完成凝练或冲穴。

## 生命周期与真实准备

`Player::Zhuji` 保存单次筑基状态。`preparing` 先扣旧突破报价所需灵石、玩家选择的0至6枚凝元丹及可选1枚灵核，冻结真实天赋，进入90天突破安排。实际世界事件或斗法中断时按现有安排机制恢复；完成闭关才进入 `active`。不再额外抽取旧突破成功率。

五行入关抽首轮自然气及每丹2点随机五行；第4轮灵核提供4点随机气。自然气、丹药、灵核、聚气使用独立局部随机流；报价只在克隆上运行，未来五行组成不对外公布。普通跨轮保留8点，道体10点。稳灵阵没有正式来源，因此不暴露免费开关。天赋按角色真实 trait / talent 派生，不接受客户端自填。

已经服用且冻结目标为当前炼气后期的突破丹，在入关时转成1份筑基丹准备，提供五行2气或周天15真气；计入每局6份上限，最多再从库存选择5枚，不重复扣已服丹药。其他境界的突破准备不消费、不跨境生效。

周天每丹增加15真气，基础100。道体每次冲穴少耗1气，道心坚毅主关成功率加10个百分点；普通穴2次、主关3次。失败耗气和次数，留在原处。灵核只恢复刚失败且未改冲或离位的穴位次数，不退真气。首次成功得分并触发窥见、蓄势、聚气、通络等既定效果；已开穴回走耗1气，不重复奖励。三关各通一处并回丹田后，归元额外20分。

成功时按原大突破规则升境、更新寿元、声望、成就和天赋，并增加 `max(0,min(120,score)-100)` 永久基础气血。该基数先经过2.4，再经过功法与体魄乘区；原型裸等效值仅作说明。成功根基不能重开或补修。失败及主动收功按冻结旧失败比例扣修为，准备与时间不退，可以重新准备；新尝试继承递增修订号及旧动作收据，避免旧入关请求重复扣费。金丹、元婴等后续突破及旧在途突破安排维持原概率路径。旧已筑基角色不补发、不开放补修。

准备或活跃期若因正常人生结算结束，该局终止为已结算的收功状态，不额外扣一次失败修为；旧在途突破安排仍按原逻辑处理。

## 与丹药、气血的关系

玩家当前气血和最大气血均使用绝对点数，体魄丹增加 `Arts::BaseHealthBonus`，筑基超额分增加独立的 `Arts::FoundationHealthBonus`，两者共同进入权威生命公式。原 `hpBonus` 仍保存旧倍率含义。预览的基础值、裸2.4等效值及当前构筑实际最大值增量应分别展示，不把根基当成伤害或直接加到当前气血。

疗伤、续命及NPC边界采用[丹药实际效果](PILL_EFFECTS.md)中的正式规则。寿元丹的 `Person::PillLifeBonus` 独立封顶500年，筑基按原规则更新境界寿元并保留天赋和丹药总加成。旧玩家百分比气血由主存档的 `healthRulesVersion` 迁移一次；不以气血值是否小于100推断版本。

## 协议与持久化

`GET /api/zhuji` 返回公开快照。`POST /api/zhuji` 按 `kind` 严格解析：

- `start`：`route` 为 elements/meridians，`pills` 为0至6整数，`core` 为布尔值，另带 `revision/requestId`。
- `quote`：`revision/action`，不推进活动时钟、共享或局部RNG，不写档。
- `action`：`revision/requestId/action`。五行动作使用 `kind/spend/targetId/keep` 的适用子集；周天冲击与移动只接收 `kind/targetId`。
- `bind`：`revision/requestId/spell`，成功定型后设置或更换本命的旧协议适配。新界面统一使用`POST /api/arts/lifebound {spellId}`。

未知字段、非法ID、类型、负值及小数均明确拒绝。动作先验证版本与幂等收据，成功后记录新修订号；同请求重放不重复扣费，内容不一致则拒绝。新局期间其他写动作由统一策略阻止，准备中的世界中断仍可解决。

codec 位于 `persistence/zhuji_codec.*`，全部字段严格校验，私有随机流放 `rng` 数组并使用uint32范围；失败损失键为 `breakthroughFailureLoss`，适配通用浮点白名单。旧缺字段默认无筑基局。局部codec先解码临时值，成功才替换；主save负责角色境界、工作和结算状态的一致性及检查点快照往返。

## 本命与前端

五行路线记录固有、周天路线记录保留。成功后在神通界面的单一本命槽选择或更换当前境界已领悟的普通神通，包含普通攻击与普通防御；无需当前携带，不增加携带槽。战斗、秘境、工作、事件或未结算筑基期间不可更换；空闲时允许A→B→A，不收取额外费用。卸下神通保留槽内选择，但不入牌组就不生效。不可补修的是筑基路线和根基收益，所选本命神通不永久锁定。只作用于携带该神通时生成的第一张副本，同名另一副本不受影响。固有占正常首手位置，保留占正常手牌容量，主动弃牌仍遵循原规则。战斗冻结、抽牌、回合末处理由combat统一负责。

`web/zhuji.mjs` 导出 `mfRenderZhuji(View,{busy})`、`mfBindZhuji(Host,Hooks)`、`mfAcceptZhuji(View)`、`mfResetZhuji()`。Host为独立容器；Hooks支持 `request(Body)`、`onState(State)`、`setBusy(Bool)`、`isBusy()`，并提供由账号稳定标识与View.lifeId组成的 `scope`。无Body时请求GET，有Body时请求POST，返回原始JSON。主app接收完整state后正常重绘，并重新绑定新Host。

成功接受新建、读取、导入、检查点恢复之前，以及登出或账号失效时，主app应调用 `mfResetZhuji()`；即使读回同一人生的旧进度，也必须清理待重试动作、错误与确认。模块还会在lifeId或账号scope变化时自动清理。每项异步请求冻结scope、重置世代与操作编号，旧响应不能发布旧state，旧finally不能释放新操作的busy。

前端保留A明亮罗盘及B可滚动经脉图。换气来源只暂存在界面，目标点击才提交；选穴只展示报价，主动冲击才提交。使用局部busy、修订号、异步报价序号和同请求重试处理重复点击、过期响应与失败恢复。关键入关、散去余气、永久定型展示具体确认；成功面板只提供前往神通页设置本命的入口，不再提供永久绑定弹窗。

桌面宽度至少761px且视口高度不超过900px时压紧面板和标题，经脉图高440px；高度不超过800px时图高420px。通用规则默认折叠，当前选穴的后端效果、耗气、成功率及动作保持展开。手机保留地图横向滚动与详情纵向滚动，布局不锁定整页高度。
