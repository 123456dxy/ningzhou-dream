# 天气背景音乐

经典电脑界面与手机界面共用 `web/weather-music.mjs` 播放器和 `web/music-controls.mjs` 控件。顶部“音乐”以及“存档与设置”内的音乐入口都能打开同一常驻对话框。

默认关闭、音量 25%、自动随天气。玩家首次开启后开始加载所选曲目，普通重绘不重新播放；之后同一浏览器记住开关、音量和自动／手动模式。浏览器需要用户手势时提示点击播放。选“自动”后按已有的 `state.world.weather` 切曲；手动选曲时保留所选音乐。

| 白名单曲目 ID | 天气 | 游戏音源 |
| --- | --- | --- |
| sunny | 春和景明、秋高气爽 | 晴山·松间初照 |
| rain | 烟雨绵延、灵雨润山 | 听雨·檐下观心，采用柔雨修订版 |
| wind | 长风过境、朔风凛冽 | 长风·山中问道，沿用空山版旋律的循环导出 |
| mist | 薄雾锁江 | 江雾·隔岸闻笛 |
| clouds | 云蒸霞蔚、丹霞映天 | 云霞·天光入岫 |

未知或尚未载入的天气默认选择晴山。现有开局和年度两套天气文案均已覆盖；本次不改变天气生成、存档或数值规则。

## 播放与资源生命周期

- 只有玩家开启音乐后才创建音频、请求所选文件；不预载整套曲目。
- HTMLAudio 负责流式播放，支持 WebAudio 时使用 GainNode 控制音量；不支持时回退元素音量。
- 天气或手动曲目变化约 4 秒交叉淡化，最多保留两路音频；同类天气不重播。同一时刻快速改选会丢弃过期结果并释放不用的资源。
- 切换失败时尽量保留原曲，显示重试入口。音频错误不进入游戏命令，不阻止操作或存档。
- 页面后台暂停，回到前台恢复既有曲目位置。播放器销毁时移除事件、取消过渡并释放媒体与音频图。
- 偏好仅存于本地键 `nz-weather-music-v1`；版本、类型、音量与选曲 ID 有校验。存储不可用不阻断播放，不把偏好加入玩家存档。

音源在 `web/assets/music/`，五个固定 ASCII MP3 路径只由客户端白名单选择。全部为 44.1 kHz 双声道、192 kbps，从对应循环 WAV 编码，没有额外首尾淡出；来源、版本、校验与许可见该目录 README 和 manifest。播放器不会把请求或存档中的字符串当资源路径。

## 本次接口影响记录

| 项目 | 核对结果 |
| --- | --- |
| 目标与入口 | 新增客户端播放器；经典 `render()` 与手机 `render()` 同步天气，独立音乐面板负责本地控制 |

| 运行条件 | 首播需要浏览器允许的用户手势；网络错误和后台生命周期有恢复路径，不访问游戏 RNG／日历 |
| 资源交付 | CMake 与静态 VS 递归复制 `web`；已有本地和服务器发行脚本包含 MP3。新增前端源码需运行 VS 工程生成器 |
| 传输 | 实际 Chromium 可解码当前服务返回的 MP3；本轮不修改 HTTP MIME、Range 或认证实现 |

手机界面启动先读取既有 `/api/mode`。只有服务端明确返回 `local: true` 才跳过本地模式已禁用的 `whoami`，直接载入本地角色与天气；联机模式继续请求 `whoami`，保留 401 登录处理。模式读取失败或字段异常会展示错误，不会被当作本地模式。

## 验证入口

```powershell
node tools/check-weather-music.mjs
node tools/check-weather-music-browser.mjs --binary <本轮构建的ningzhou_web.exe> --playwright <本机Playwright模块路径>
python tools/generate-vs-projects.py
```

浏览器脚本使用独立程序副本、随机端口、临时本地角色与存档目录。媒体播放／音频管线来自实际浏览器，天气映射部分仅覆盖接口返回中的天气标签，其他游戏响应仍来自真实隔离服务。各轮实际通过数量与截图以 `build/weather-music-integration-20261017/` 中当轮记录为准。
